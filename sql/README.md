# MySQL 분석 코드 실행 안내

제공된 팀 분석 SQL의 파일명과 데이터 입력 경로를 정리한 버전이다. 탐색용 SELECT, 진단 쿼리, 생성 쿼리가 섞여 있어 번호순 전체 일괄 실행을 보장하지 않습니다. 원본 학습·분석 과정을 보존한 자료로 활용하세요.

## 환경과 준비

- MySQL 8.0: 윈도 함수 `NTILE`, `ROW_NUMBER`와 CTE, `utf8mb4_0900_ai_ci` 사용
- 다른 테이블이 없는 별도 분석 데이터베이스에서 작업
- `01_create_and_load.sql`의 `/ABSOLUTE/PATH/TO/data/raw/`를 실제 CSV 폴더의 절대 경로로 수정
- `LOAD DATA LOCAL INFILE`을 사용하므로 클라이언트·서버의 허용 설정과 권한 확인 필요. 원본에는 `SET GLOBAL local_infile` 설정 구문이 포함됨
- 원본은 `NETFLIX`와 `netflix` 표기를 혼용. 대소문자를 구분하는 서버에서는 같은 이름으로 맞춰야 함

## 단계와 의존성

| 파일 | 목적과 실행 조건 |
| --- | --- |
| 01 | 데이터베이스·원본 테이블 생성 및 CSV 로드 |
| 02 | 원본 데이터 구조·중복·오류 확인 |
| 04 앞부분 | 원본 테이블을 `raw_` 이름으로 변경 |
| 03 | 결측·이상치 및 대체값 진단. `raw_` 테이블이 필요하며 일부 쿼리는 `clean_movies`도 참조 |
| 04 나머지 | `clean_` 테이블 생성 및 전처리. 03과 필요한 진단 구간을 오가며 확인 |
| 05 | 정제 테이블의 그룹별 집계 |
| 06 | 사용자별 행동 요약과 `user_activity_summary` 데이터마트 생성 |
| 07 | 세그먼트 탐색 후 Version 2의 `user_behavior_segment` 생성 |
| 08 | 세그먼트별 주요 지표 비교 |
| 09 | 최종 SELECT 결과를 CSV로 수동 내보내기 |

`07`에는 Version 1과 Version 2가 함께 있다. 최종 데이터마트는 Version 2를 기준으로 하며, 같은 테이블이 이미 있으면 CREATE 문을 그대로 다시 실행할 수 없다. `09`는 파일을 직접 생성하는 명령이 아니라 CSV로 내보낼 SELECT 쿼리이다.

## 원본 코드의 재현 제약

- 일부 대체값·상한값은 당시 진단 결과를 숫자로 입력한 방식이다.
- `NTILE`에서 동률을 정렬하는 보조 키가 없어 환경에 따라 경계 사용자의 세그먼트가 달라질 수 있다.
- `CURDATE()` 기반 지표는 실행 날짜에 따라 달라집니다.
- 원본 LOAD 구문은 빈 문자열·날짜 변환이 서버의 SQL 모드에 영향을 받을 수 있다.
- 이번 정리에서는 MySQL에 접속하거나 SQL을 실행하지 않았다.
